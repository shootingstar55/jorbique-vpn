# Обновление и откат (macOS)

`jorbique-vpn-admin` ставит, обновляет, откатывает и удаляет клиент. Скрипт
идёт вместе с клиентом: `/usr/local/libexec/jorbique-vpn/jorbique-vpn-admin`,
доступен в PATH как `jorbique-vpn-admin`. Так сделано специально: откат
нужен именно тогда, когда на машине уже стоит неудачная сборка, а это
худший момент, чтобы просить сначала склонировать репозиторий.

Имя файла `.pkg` всегда начинается с версии, например
`v2.13.3-Jorbique-VPN-macOS.pkg`. В примерах ниже используется такое имя,
но версия у конкретного файла будет своя.

Любая команда, которая что-то меняет, требует root и дописывает
выполненные действия в `/Library/Logs/JorbiqueVPN/admin.log`. Любая
ошибка завершает команду с ненулевым кодом выхода.

## Что установлено прямо сейчас

```bash
jorbique-vpn-admin status
```

Показывает установленную версию, где лежат бинарники и данные,
загружены ли демон и меню-бар, и на какую версию откатит `rollback`.

## Обновление

```bash
sudo jorbique-vpn-admin upgrade ~/Downloads/v2.13.3-Jorbique-VPN-macOS.pkg
```

Порядок действий:

1. останавливает туннели и выгружает демона;
2. снимает снапшот текущей установки в
   `/Library/Application Support/JorbiqueVPN/rollback`: бинарники,
   конфигурацию и скачанные профили, app bundle и оба plist'а launchd,
   с пометкой версии, из которой они взяты;
3. запускает установщик;
4. загружает демона снова;
5. запускает проверку работоспособности.

Проверка отвечает на вопросы, которые отличают удачную установку от
неудачной:

- бинарник вообще запускается;
- launchd показывает демона загруженным;
- демон реально слушает свой control-сокет (джоб, который launchd
  запустил и который тут же умер, формально загружен, но бесполезен, и
  любой запрос туннеля к нему завершится ошибкой);
- клиент может прочитать свою конфигурацию и сообщить состояние своих
  туннелей, а для этого проходит тот же путь, что и обычный запуск.

Проверка не доходит до реального поднятия туннеля. Если удалённый
сервер не отвечает, это не вина новой сборки, а откат релиза из-за
недоступного сервера принесёт больше вреда, чем найденная им проблема.

Если установщик или проверка завершились с ошибкой, снапшот
восстанавливается автоматически, а команда завершается с ненулевым
кодом: машина остаётся на прежней версии. Если восстановить снапшот не
удалось, демон всё равно запускается заново, а в сообщении об этом
прямо говорится: такая машина оказалась между двумя сборками и ей нужен
`.pkg` вручную.

Одновременно может выполняться только одна из этих команд. `install`,
`upgrade`, `rollback` и `uninstall` берут блокировку в
`/Library/Application Support/JorbiqueVPN/.admin.lock`; повторный запуск
откажется работать, а не будет снимать снапшот с дерева, которое первая
команда ещё не докопировала. Если блокировку оставила машина, потерявшая
питание, в ней записан pid, которого уже не существует, и такая
блокировка снимается сама.

Логи и DNS-кэш в снапшот не попадают. Старые логи специально оставляют
на месте: они пригодятся тому, кто будет разбираться с неудачным
обновлением.

## Откат

```bash
sudo jorbique-vpn-admin rollback
```

Восстанавливает снапшот (бинарники, конфигурацию, app bundle,
plist'ы), перезапускает демона и проверяет результат тем же health
check. Чек версии, на которую был апгрейд, забывается, поэтому `status`
и любое следующее обновление сравнивают версии по тому, что реально
лежит на диске.

Снапшот всего один: версия, которая стояла до последнего обновления.
Чтобы откатиться дальше, нужно поставить нужный `.pkg` напрямую.

## Первая установка

```bash
sudo jorbique-vpn-admin install ~/Downloads/v2.13.3-Jorbique-VPN-macOS.pkg
```

То же самое, что двойной клик по пакету, плюс проверка работоспособности.
Снимать снапшот пока не с чего, поэтому при ошибке откатываться не на
что.

## Удаление

```bash
sudo jorbique-vpn-admin uninstall           # оставляет конфигурацию и профили
sudo jorbique-vpn-admin uninstall --purge   # удаляет и данные тоже
```

Удаляет бинарники, app bundle, симлинки в PATH (`jorbique-vpn`,
`jorbique-vpn-admin`), оба джоба launchd и чек пакета.
Без `--purge` всё, что лежит в
`/Library/Application Support/JorbiqueVPN`, остаётся на месте, поэтому
следующая установка найдёт конфигурацию и скачанные профили там же, где
их оставили. `--purge` дополнительно удаляет файлы того пользователя, от
чьего имени выполняется команда: `~/Library/Application
Support/JorbiqueVPN`, `~/Library/Logs/JorbiqueVPN`; у
остальных пользователей на машине их файлы остаются нетронутыми.

## Конфигурация

`vpn_cfg.json` переживает обновление дважды: `preinstall` пакета
копирует его в сторону, а `postinstall` кладёт обратно, и вдобавок его
копия хранится в снапшоте. Удалить его может только
`uninstall --purge`.

## Посмотреть план заранее

```bash
jorbique-vpn-admin --dry-run upgrade ~/Downloads/v2.13.3-Jorbique-VPN-macOS.pkg
```

Печатает все шаги вместо того, чтобы их выполнять, и не требует root.
Этим же способом шаги читают и тесты.

## Тесты

`scripts/admin_script_test.go` читает план действий;
`scripts/admin_upgrade_test.go` прогоняет его целиком: разворачивает всё
дерево установки во временном префиксе (`JORBIQUE_VPN_ADMIN_PREFIX`),
обновляет 2.11.5 → 2.12.0 и откатывает обратно, плюс отдельно проверяет
сборку, которая не проходит health check, и установщик, который падает
сразу, и в обоих случаях дерево должно остаться на той версии, с которой
начали.

```bash
go test ./scripts/
```
