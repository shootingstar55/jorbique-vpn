# Обновление приложения

Начиная с 1.12.0 главное окно на Windows, macOS и Android проверяет последний
стабильный релиз `shootingstar55/jorbique-vpn` при открытии и раз в шесть часов.
«Проверить обновления» запускает проверку вручную. Сбой фоновой проверки не
мешает подключению. Баннер новой версии предлагает «Обновить» с подтверждением.
Первый переход с 1.11.x на 1.12.0 выполняется обычным установщиком: старые версии
ещё не содержат этой кнопки.

Клиент получает метаданные через официальный HTTPS API GitHub. Принимаются только
стабильные версии vX.Y.Z и пакет своей ОС с корректными размером и SHA-256.
Данные кабинета и UUID в GitHub не передаются. Сам пакет загружается только с
GitHub и его конкретных серверов release-assets/objects.githubusercontent.com;
перенаправление на HTTP или другой хост отклоняется. Ответ метаданных ограничен
1 МиБ, пакет — 256 МиБ. Скачивание потоковое в приватный временный каталог,
неполный пакет удаляется. Перед установкой версия проверяется повторно; установки
той же и более старой версии запрещены.

Windows хранит пакет и помощник в случайном каталоге системного Temp с защищённым
ACL только для Administrators/SYSTEM, установленным при создании каталога. Затем скачивает ZIP, завершает VPN и закрывает клиент. Отдельная копия старого
клиента получает проверенные метаданные от фактического родителя по приватному
каналу и подтверждает готовность до закрытия приложения. Поэтому установка
не требует доступа к GitHub после отключения VPN. Помощник проверяет пакет ещё раз,
определяет исходный EXE по процессу-родителю,
проверяет совпадение своего и исходного файла и ждёт завершения процесса. Из
архива допускается только Jorbique-VPN-Extended.exe. Подмена выполняется через
временный файл рядом с приложением, при ошибке запуска возвращается старый EXE.
Если восстановление не удалось, резервный файл сохраняется. Настройки не удаляются.
Путь установки и команда запуска не принимаются из веб-интерфейса. Windows удаляет
заблокированный файл помощника после перезагрузки.

macOS открывает проверенный PKG в системном Installer. Android открывает системный
установщик через закрытый FileProvider с временным разрешением чтения только APK.
Проверяются имя пакета, увеличение versionCode и точное совпадение сертификатов
с установленным приложением. Установка требует обычных разрешений ОС; скрытой
установки и обхода системных подтверждений нет.

SHA-256 из GitHub API подтверждает соответствие загруженному release asset, а не
независимую подпись издателя. Доверие остаётся у аккаунта GitHub, процесса выпуска
и системного хранилища CA. Windows и macOS пакеты пока не имеют коммерческой
подписи издателя. Android использует существующий постоянный ключ релизов.

Проверки: тесты неверной версии, отсутствующей SHA-256, превышения размера,
повреждения/усечения пакета, запрещённых редиректов, Zip Slip/лишних файлов,
подмены исходного EXE и восстановления после ошибки запуска; тесты интерфейса
двойного нажатия и фоновых сбоев; JVM-тест политики подписи Android.
Полный системный цикл обновления на Windows/Android требует проверки на устройствах.
